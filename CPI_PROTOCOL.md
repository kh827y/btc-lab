# CPI-001 — первая проверка добавочной ценности CPI
Статус: до просмотра development-метрик; итоговые CSV не открывались в текущей работе. Исходный протокол Astra от 26.11.2026. Это фиксированная первая спецификация, не обещание эффекта.

Гипотеза: базовый CPI м/м (факт минус строго дорелизный прогноз, п.п.) улучшает прогноз доходности BTC через 7 суток после того, как первые 30 минут реакции уже известны. Сравнить одинаковые даты, модели с/без CPI. Основная выборка 102: 46 train, 24 development, 32 test. Не использовать нестандартные релизы в основном тесте; раннее раскрытие исключается как ретроспективная особенность, отдельно проверять применимость правила без этого исключения в будущей проверке. Две даты без предшествующих закрытий исключены, не заполнять.

Модели: нулевой прогноз, среднее прошлых исходов, линейная регрессия с константой по 28-дневной доходности и волатильности, затем + реакция 30 минут, затем + core CPI surprise. Нормировка исключительно по завершившейся обучающей истории, least squares; постоянный признак центрируется в ноль на обучении. Параметры не перебираются. При каждом решении расширять обучение только завершившимися исходами, доступными к +30 минутам. Не использовать цену открытия +31 как признак. Основное сравнение — RMSE market_plus_cpi минус market_after на одинаковых событиях. Дополнительно MAE, доля отсрочек, изменение количества купленного BTC при той же сумме. Если прогноз отрицателен — ждать ровно 7 суток, иначе купить +31. Доходность денег 0; одинаковая пропорциональная комиссия/спред/проскальзывание при одной покупке в каждом сценарии сокращается в отношении количеств BTC. Различающиеся издержки и доходность денег проверять отдельно, не делать вывод о доходности портфеля. Не выбирать порог по тесту.

Сейчас — development replay, проверить механику, результат не независимый. До открытия test: зафиксировать критерий практически значимого эффекта (обсудить с владельцем либо показать диапазон без бинарного решения), интервалы неопределенности (парный блочный bootstrap, фиксированные seed и длины блоков), альтернативы прогнозов, последние 24h, чувствительность к годам/событиям, позднему входу, издержкам. Отдельно для исследования немедленной реакции (часть A) проверить календарь контролей; для основного прогноза (часть B) не удалять последующие неожиданные события. Независимый BTC/USD (Kraken или другой документированный независимый источник с проверенным временем и покрытием) нужен для проверки устойчивости; не сшивать с Binance. Если неполон, честно ограничить вывод. Гипотезы о направлении и волатильности отдельно. Нет гарантии нетронутого holdout до проверки журнала пользователя; не выдавать исторический тест за перспективный.

Версия входа зафиксирована хэшами CPI и audit в коде; development читает только четыре CSV train/development с хэшами из coverage. Файлы test организационно закрыты, не защищены правами ОС. Никаких вызовов LLM, никаких платных источников. Отрицательный/неопределенный результат сохраняется.

## Поправка после аудита, до итогового теста
Development уже просмотрен, спецификация прогнозов сохранена без подгонки. Первоначальный отчёт: 24 события, RMSE 9,84 (нулевой), 10,78 (market_after), 10,95 (market_plus_cpi) п.п. Теперь CPI-v2 хранит стабильный snapshot SHA-256 из проверенного списка ZIP и запрещает изменение ранее полученных train/development CSV. При обычной подготовке 2024+ не вычисляются; ранее созданные производные test CSV удаляются при проверенной миграции. Финальная команда пока отсутствует. Не считать raw данные или историческое знание LLM изолированными. Следующая версия протокола уточнит интервалы и критерии до открытия итоговой выборки; старый development остаётся зафиксированным.
