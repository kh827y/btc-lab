# Правила для ИИ-разработчика

Этот проект — личная исследовательская лаборатория BTC; **сейчас реализована только локальная панель отображения** агрегированных рыночных данных. Не изменяйте `btc-market-data`, GitHub Actions, настройки мониторинга BTC и внешние источники без отдельного поручения.

1. **Не заменяйте** `null`, `stale`, `incomplete`, `invalid`, `unavailable` и `unverified` на 0 или на данные другого состава бирж.
2. Для каждой добавляемой метрики сначала найдите точный путь `brief.json`, качество в `metric_quality.checks`, единицу измерения, момент наблюдения и корректность выборки.
3. Не рисуйте исторические временные ряды из одного снимка JSON, не называйте скриншот стакана исполненными сделками и не смешивайте когорты держателей с разными определениями.
4. Код текущих метрик держите в `data_logic.py`, исторических — в `history_logic.py`, визуализации — в `app.py` и `history_page.py`.
5. После изменения логики запускайте `python -m unittest discover -s tests -v`. Добавляйте проверки на пропуски, даты и перепутанные выборки.
6. Обновляйте `ARCHITECTURE.md` и `README.md`, если меняете структуру или способ работы. Описывайте изменения простым русским языком.
7. Не добавляйте платные API, ключи, автоторговлю, LLM-вызовы, новые серверы или фоновые процессы без отдельного решения пользователя.

8. Перед добавлением исторических рядов сверяйте DATA.md с фактическими файлами. Даты измерения, публикации и загрузки различайте. Не используйте исторические данные в бэктестах без проверки доступности на момент сигнала. Не сохраняйте секреты или большие архивы в Git. Предпочитайте готовые проверенные библиотеки.

9. Исторические графики не являются подтверждением доступности данных в прошлом. Не интерполировать пропуски, не смешивать корзины, не использовать дату наблюдения как дату публикации без проверки.

10. С 26.11.2026 разработка только через GitHub: изменения в main после проверки, пользователь обновляет локальную копию через update.bat (git pull --ff-only). Схема Google Drive / Apps Script / автоматический импорт кода отменена; не восстанавливать её. Это не относится к независимому мониторингу BTC и доставке его уведомлений.

11. Приоритет исследований — практическая ценность для решений о покупке/ожидании и риске BTC. Изучать как направление/смену тренда, так и риск/волатильность, новости/ожидания и небольшие обоснованные сочетания факторов. Завершить CPI как ограниченный пилот, начать перспективный журнал, затем 2–3 ручных исследования до агентного контроллера. Не считать доминирование любого фактора доказанным заранее. Не строить универсальную инфраструктуру до практической потребности.

12. Актуальный короткий план — ROADMAP.md. Перед очередным этапом оценивайте, принесёт ли Astra (Work) существенную пользу в методологии, поиске источников, сложной архитектуре или независимой проверке. Если да, заранее предупредите пользователя, объясните цель и подготовьте самостоятельное задание с ожидаемым результатом и рекомендуемым усилием. Пользователь сам передаёт задачу Astra. Обычная реализация и исправления остаются в чате; не использовать Astra ради расходования лимита и не дублировать работу без причины.

13. Владелец согласовал внешние LLM API для агентной части. Разрешены только согласованные поставщики/модели, фиксированные HTTPS-адреса, явные бюджеты и контролируемые read-only инструменты. Не передавать секреты, приватные данные без оценки условий, не исполнять команды/код LLM. Платные вызовы запускает владелец; не повторять бенчмарки и поиск API. См. ROADMAP.md. Рабочая система агентов ещё не создана; тестовые harness — материал для переиспользования после ревью. Расчёты выполняет код, не LLM. Фиксировать все гипотезы, версии данных, исключения, отрицательные результаты и неопределённость.

14. На старте один уровень руководства (Sol High API, Astra API только опциональная замена/эскалация), DeepSeek High как основной работник, MiniMax только при доказанной потребности. Активный поставщик — CheapVibeCode; Surplus/Mistral не подключать и не пополнять. Не считать идентичность моделей у посредника подтверждённой. Официальный ChatGPT Plus/Work использовать вручную для разработки и наиболее важных методологических решений/аудита. Большие данные обрабатывать локальным кодом; моделям предоставлять ограниченные проверяемые инструменты и компактные результаты. Не наращивать иерархию, параллелизм и расходы до проверки практической пользы.

15. Владелец получил доступ к Claude Opus 5.5 через Hoplite (идентичность маршрута и возможности независимо не подтверждены). Использовать вручную для независимого аудита кода, методологии и плана, при необходимости проектирования минимального контроллера. Промпты для Opus только на английском. Веб-поиск не предполагается; не поручать сбор внешних источников без подтверждения доступа. Доступ к репозиторию только в необходимом объёме, предпочтительно read-only/изолированная копия; не передавать ключи, локальные частные данные и итоговую CPI-выборку до заморозки протокола. Не разрешать правки main или произвольные платные вызовы; сначала отчёт и проверка замечаний. Лимит до 01.12.2026 — возможность для полезного аудита, не причина придумывать работу. Это не новый автоматический поставщик и не дополнительный уровень агентной иерархии.

16. До итогового теста фиксировать гипотезу, версию данных, метрики/критерии, весь перебор и исключения; не использовать итоговые исходы через агентные инструменты. Учитывать зависимость перекрывающихся горизонтов, смену режимов и неопределенность. Исторические результаты и перспективные прогнозы различать. Сравнивать решения на одинаковом капитале и временном горизонте, учитывать упущенный рост, издержки и риск; продажи определяет владелец. См. ROADMAP.md.
