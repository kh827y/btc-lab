# BTC-Lab: Docker + GitHub Actions + Brave

Единственный локальный изолированный маршрут — Docker Desktop с Linux containers / WSL 2. Windows Sandbox отменена. Docker устанавливается владельцем на D:\Docker, WSL storage D:\DockerData\WSL. Системные компоненты Windows/WSL и часть настроек остаются на C. Не переносить вручную системные каталоги.

## Установка
1. Закрыть прежнюю песочницу, отключить Windows Sandbox в optionalfeatures.exe, перезагрузиться при необходимости. Не отключать WSL, Virtual Machine Platform или аппаратную виртуализацию. Вручную можно удалить только созданную для пробы D:\Проекты\btc-lab\data\sandbox_probe. Исторические архивы не удалять.
2. Скачать x86_64 Docker Desktop Installer.exe с https://docs.docker.com/desktop/setup/install/windows-install/ в D:\. PowerShell администратора:
   Start-Process 'D:\Docker Desktop Installer.exe' -Wait -ArgumentList 'install','--accept-license','--backend=wsl-2','--installation-dir=D:\Docker','--wsl-default-data-root=D:\DockerData\WSL'
   Запустить Docker Desktop, выбрать Linux containers/WSL 2. До загрузки образов проверить Settings > Resources > Advanced > Disk image location — на D. Если отличается или Docker требует обновить WSL, остановиться и сообщить владельцу.
3. Приватный kh827y/btc-lab-bridge уже создан, доступ ChatGPT проверен. PAT fine-grained только Contents Read and write на этом репозитории. Telegram бот уже создан. Ключи вводить только локально.
4. Один раз update.bat, затем setup_local_runner.bat. Setup проверяет D:\Docker\resources\bin\docker.exe, локальный Linux engine и свободное место, скачивает официальный python:3.12-slim и закрепляет ID образа, копирует фиксированный контроллер под data/local_runner. Не перезаписывает установленный контроллер; при частичной установке не удалять файлы вслепую.
5. В Brave отключить старую копию расширения (D:\Проекты\btc-lab\browser_bridge), загрузить фиксированную копию D:\Проекты\btc-lab\data\local_runner\browser_bridge. Открыть именно этот чат, ввести pairing key, включить. Запустить data\local_runner\start.bat. Сначала проверить сквозной цикл под наблюдением.

## Протокол
- job.json в PRIVATE mailbox: ровно id (уникальный ASCII <=64, без Windows reserved names), commit (точный 40-символьный SHA), task. Один job за раз, следующий после анализа результата. results/<id>.json immutable. task market_state: помощник обновляет cloud_job.json (id/task) в main kh827y/btc-lab, запускается market_state_check.yml, облачный run по точному SHA, timeout 6 min, только публичные данные и read-only token. Ретранслятор сообщает run_id; помощник читает логи/артефакт. Успешный workflow не гарантирует полноту данных.
- task archive_check: exact current official main, скачиваются только docker_archive_task.py и binance_minute.py. Выполнение только в локальном Linux-контейнере; два фиксированных read-only mounts (копия кода и data/binance_1m). Сеть отключена, read-only root FS, непривилегированный пользователь, no-new-privileges, все capabilities сняты, 2 CPU, 2 GiB RAM, 64 PID, tmpfs 32 MiB, без Docker socket, токенов или иных папок хоста. Только stdout возвращается на хост, JSON <=128 KiB и общий вывод <=256 KiB, timeout 300s. Новые отчёты внутри data/local_runner/jobs/<id>. Выбранные daily/monthly ZIP проверяются по SHA и парсеру минутных свечей; это readiness, не новое исследование. Не копировать архивы в образ. Проверка свободного места C >=2 GiB, D >=512 MiB — не жёсткая квота. Удаляется исключительно собственный временный контейнер по полному ID, никаких prune, удаления архивов или чужих контейнеров. При неизвестном состоянии контейнера requires_owner и immutable needs_owner.json, новые job блокируются. Docker не является абсолютной изоляцией. Новые источники, папки, зависимости и ограничения согласовать отдельно.
- Фиксированный локальный контроллер и расширение не обновляются автоматически. Никаких произвольных команд, shell, git pull/исполнения скачанного Python на хосте. PAT и Telegram token DPAPI текущего пользователя. HTTP loopback 127.0.0.1:18746 с pairing key. Brave — явно выбранный чат, только composer/кнопка отправки, не извлекать ответы модели, не обходить лимиты/капчи, не повторять неопределённую отправку; максимум 20 попыток на ручное включение. Неофициальная интеграция, прекращать при несовместимости или запрете.
- progress.json: id уникальный ASCII <=55, kind progress/attention, text одна строка <=200 символов. Только существенный текущий этап 🔧 или реальный запрос участия 🚨❗. Никаких уведомлений о штатных тестах/результатах/исправимых ошибках. attention приостанавливает новые задания до явного ответа владельца и замены progress.json. Telegram не принимает команды. Ctrl+C останавливает исполнитель, «Остановить» отключает расширение. Не использовать Codex, ChatGPT Tasks, дополнительные модели/API/swarm. Fable/Opus prompts English. Не менять мониторинг или замороженные журналы, не открывать исходы без разрешения.
- До проверки на реальном Windows Docker, Telegram, Brave и полного цикла не оставлять без наблюдения. Не утверждать автономность до получения результатов. 

## Контроль доставки и ручное обновление
Расширение после нажатия отправки до 10 секунд проверяет только состояние composer/stop control; это не подтверждение сервером. При недоступной отправке останавливается, без повторов. Если claim без ack дольше 5 минут, либо тот же job остаётся без продолжения 90 минут после claimed click, ретранслятор один раз просит проверить Brave/лимит/завершение этапа; это не доказательство лимита чата. Уведомления не повторяются, результат сохранён. Не обходить лимиты и не открывать новый чат автоматически. При явном завершении этапа помощник ставит progress attention, если требуется участие владельца. Для обновления уже установленной копии: выключить расширение, остановить start.bat, update.bat, refresh_local_bridge.bat (только два фиксированных файла, backup исходных модулей, смена pairing key, PAT/Telegram без изменений), перезагрузить фиксированное расширение в brave://extensions, привязать текущий чат новым ключом и запустить start.bat. Не отправлять pairing key в чат.

## Исправление зависшей очереди
Контроллер проверяет текущий job.json даже при ожидающем уведомлении. Только явно опубликованный новый валидный ID заменяет ещё не востребованное старое событие; старый результат сохранён, локальный маркер superseded исключает его повторную отправку. Не повторять уже востребованные сообщения. Состояние busy определяется по видимой кнопке остановки в области composer текущего чата; реальная генерация и черновик остаются блокирующими. Popup обновляется при изменении статуса и показывает ID ожидающего задания. Ручной refresh теперь обновляет фиксированный controller.py, local_relay.py, worker.js, popup.js с локальными резервными копиями и новым pairing key. Старые ключи GitHub/Telegram не меняются. Docker archive-probe-001 успешно проверил 1440 и 44640 минутных строк без пропусков, 3.55s включая старт/завершение контейнера; browser delivery пока не подтверждена.
