# Минимальный контроллер BTC-Lab (v1)

Один последовательный цикл: Sol — план, DeepSeek — анализ, тот же Sol — проверка. Это два роли/два маршрута, три обращения к моделям, без подагентов, циклов, повторов, автоматической эскалации и выбора новых гипотез. В v1 транспорт только детерминированный тестовый (DryRunTransport); никакого реального LLM/API клиента, ключей или сети. Не утверждать, что протестировано качество модели.

Руководитель возвращает строгий JSON с целью и 1–4 уникальными запросами из research_tools.dispatch. Контроллер проверяет весь план до выполнения. Затем передаёт только компактные разрешённые результаты с E1..E4 исследователю. Тот возвращает выводы со ссылками на E-идентификаторы, ограничения и следующий шаг. Руководитель получает исходные evidence и черновик, возвращает проверенную версию в том же формате. Все выходы являются текстом для человека, не разрешением на выполнение. Идентификаторы проверяются структурно, но не доказывают смысловую истинность цитаты. Нельзя выполнять даже внешне правильно сформированный совет модели. Никаких raw report/forecast/outcome, произвольных путей, произвольного shell, URL, конфигурации, root/date от модели. Инструменты только registry, study, report_integrity, journals. Никаких изменений реестра, запуска исследования или gate. Историческая confirmation остаётся заблокированной.

Бюджет v1: максимум 3 модельных вызова (Sol plan 4096, worker 8192, Sol review 6144 запрошенных output tokens), 4 локальных операции, 48 000 UTF-8 bytes на запрос, 96 000 суммарно, 12 000 bytes на ответ и 28 000 суммарно. Задача <=4000 bytes. Ошибка прекращает цикл, без retries. Это ограничения локального формата и запрошенного лимита, НЕ фактическая тарификация. Реальный транспорт должен отдельно учитывать model ID, цену входных/выходных/скрытых reasoning tokens, usage, таймауты, максимальный размер сетевого ответа, запрет redirects и явный резерв бюджета до запроса. Посредник может игнорировать лимит или тарификацию; точная гарантия расходов требует ограничения на стороне поставщика. Никакого live режима до отдельного согласования и проверки. Не передавать приватные данные/секреты внешнему API; будущая передача агрегированных метаданных требует согласованного объёма. Не менять поставщика или модели.

Запуск локального теста: .venv\Scripts\python.exe research_controller.py --dry-run
Только фиксированная диагностическая задача и canned responses, реальные локальные read-only операции. Не нужны ключи, новый пакет или отдельный bat. Missing_local_file на CI без личных архивов нормален. Проверка локального hash не является проверкой публикации/достоверности.

## Первый реальный API pilot
Фиксированный адрес https://ru.cheapvibecode.ru/v1/chat/completions, подтвержден владельцем. Sol gpt-6.2-sol high, DeepSeek deepseek-v4.1-flash-1017 high + thinking enabled. JSON nonstream, этот конкретный режим ещё не проверен. Исторические коэффициенты 1.5/.19 и возможная x3 надбавка, не подтвержденные текущие тарифы. Оценка 4.5/.57 базовых единиц за reported token; резерв до каждого запроса: UTF-8 bytes + 2048 overhead + requested output. Не освобождаем резерв за запуск. Это оценочный лимит, не гарантированный фактический расход: поставщик может добавить скрытые токены, изменить тариф или игнорировать cap. Запрашиваемые caps увеличены с 1200/2000/2000 до 4096/8192/6144, учитывая прежние High benchmarks и hidden reasoning. Три обращения по-прежнему максимум. 200000 базовых единиц — предварительный резерв, владелец подтверждает локально YES. Сверить фактический баланс до/после. TLS, fixed HTTPS, no redirects/env proxy/retries, bounded read, 240s socket timeout (не строгий wall time), usage reconciliation, stop on unknown usage, cap/model mismatch, malformed/truncated output. Model ID не подтверждает происхождение. API key вводится скрыто, не сохраняется; отказ при fallback к echoed input. Только фиктивные данные, включая провал gate, mismatch и пропущенную квитанцию; никаких настоящих архивов/журналов/реестра в пилоте. Смысловые выводы проверить вручную. Отчёт сохраняется в data/research/agent_smoke/agent_smoke_<UTC>.json; новый файл на каждую попытку, без автоматических повторов, не коммитить. Не передавать ключ в чат. Запуск update.bat, run_agent_smoke.bat, YES, key. Не запускать повторно при остановке, прислать отчёт. Контроллер dry-run CLI сохранён, paid smoke отдельный.

## Уточнение тарифа аккаунта 27.11.2026
В первом реальном запуске отображены списания Sol 708 и 2.25 тыс., DeepSeek 1.84 тыс. Владелец сообщил о персональной надбавке x5 вместо x3 при output > input. По API usage и базовым коэффициентам 1.5/.19 оценка 708 + 1832.55 + 2250 = 4790.55 базовых единиц (округление вверх по запросам 4791). UI округляет значения; точный баланс не предоставлен. Условная оценка расходов теперь x5 при completion_tokens > prompt_tokens, иначе обычный коэффициент; резерв до каждого запроса x5 для ОБЕИХ ролей, поскольку область действия надбавки не проверена для Sol. Не добавлять искусственный input для обхода тарифа. Не считать текущие цены гарантированными; новые правила тарификации требуют корректировки. Предварительный общий резерв остаётся 200000; прежний пример пилота по новой формуле резервирования потребовал бы около 174380. Если бюджет не позволяет следующий запрос, остановка без повтора. Первый nonstream pilot прошёл; повторять не требуется. Реальные метаданные ещё не подключены: следующий этап — минимизация исходящих сведений и проверка безопасности.

## Real metadata pilot (metadata-review-v1)
Отдельный run_agent_review.bat: до любого сетевого запроса локально собирает строго ограниченный снимок, показывает его и фиксированную задачу, требует YES и скрытый ввод ключа. --preview без сети и без ключа. После согласия FrozenTools использует только неизменяемые bytes в памяти, не обращается к диску по командам модели. Экспорт: ID/status 12 заранее известных исследований; числовые итоги зарегистрированного синтетического GATE-001; только enum результата сверки DVOL-001 (без хешей); счётчики и статус BUY/RISK-журналов (без дат, прогнозов, URL, receipt, доходности, файлов). Произвольные строки реестра не экспортируются. Новые ID/неизвестные статусы блокируют запуск до ручного обновления allowlist. Все сведения предварительно отображаются, фактически могут быть отправлены только некоторые; сам фиксированный промпт и сгенерированные модели тексты также передаются. Провайдер может их сохранить. Бюджет 200000 расчётных базовых единиц, три вызова, прежние модели и тариф x5. При несовпадении запроса с approved snapshot цикл останавливается, не расширяя доступ. В отчёте сохраняется approved_snapshot и итог, не API key; добавлена проверка декодированного JSON на echo ключа. Недоверенный итог даже с валидным JSON может содержать опасные советы — это текст, не команды, не выполнять автоматически и не копировать в терминал. Не полноценная OS sandbox или гарантия безопасности Python/HTTP/TLS. Не открывать реальные архивы/holdout, не запускать исследования, не править реестр или позиции. В дальнейшем расширение данных отдельно по необходимости.

## Локальные настройки доступа (после успешного metadata pilot)
Подтверждение платного запуска теперь `y` (регистр не важен); Enter/прочие значения отменяют запуск. После согласия ключ автоматически читается из Windows Credential Manager (Generic Credential `BTC-Lab/CheapVibeCode`, постоянный для текущего профиля на этом компьютере). При первом запуске скрытый ввод и сохранение через CredWriteW; при повторном ввод не нужен. Ключ не записывается в файлы проекта, Git, отчёты или параметры командной строки, не передаётся моделям как текст. Только авторизационный HTTP-заголовок фиксированного API. Для замены `.venv\Scripts\python.exe research_metadata.py --live-review --replace-key`, для удаления `.venv\Scripts\python.exe research_credentials.py --forget` или Windows Credential Manager → Windows Credentials → Generic Credentials. Без Windows или при отказе хранилища запуск прекращается, без plaintext fallback. Другой процесс с правами того же Windows-пользователя или администратор/вредоносное ПО могут получить ключ; это не защита от уже заражённого ПК. Windows API ещё не проверен на реальном компьютере; CI проверяет логику на mock-хранилище. Preview и отказ не читают ключ и не используют сеть. Сохраняется обязательное согласие на передачу данных/расходы каждый запуск.
