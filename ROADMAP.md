# BTC-Lab — единый план (27.11.2026, после двух аудитов Opus)

Цель — улучшать решения позиционного инвестора BTC (недели–месяцы, микротренды 1–4 недели): когда покупать/ждать, насколько велик риск продолжения падения, восстанавливается ли тренд, когда присмотреться к фиксации. Продажу определяет владелец. Не автоторговля. Не предполагать заранее превосходство новостей, индикаторов или риск-моделей.

1. **Готово:** локальная панель, часть истории, архив CPI (106 релизов), минутные Binance BTCUSDT с 2017-08-17 (99,38% строгих минут на 26.11.2026), подготовка CPI (102 пригодных эпизода), development replay, сравнительные тесты моделей и API. Не повторять сбор CPI или бенчмарки без конкретной причины.
2. **Сейчас:** завершить CPI-001 как ограниченный пилот исследовательского процесса, не подгонять под положительный результат. Исправить содержательное версионирование, защиту test и тестирование загрузчиков; до открытия test зафиксировать статистику неопределенности, проверки устойчивости и критерии практической ценности. Сверить независимую цену и календарь контролей там, где нужно. Отрицательный/неопределённый результат допустим; CPI не задерживает весь проект.
3. **Как можно раньше:** минимальный журнал перспективных прогнозов/решений с отметкой доступности данных, версией правила, прогнозом до исхода и сравнением с простыми базовыми моделями; недельный ритм и горизонты 7/30/90 дней. Сначала ручной/локальный режим, автоматизация только по отдельному решению владельца. Не использовать результат при формировании записи; фиксировать до исхода в проверяемой истории без публикации лицензируемых данных. Оценивать перекрытие горизонтов; журнал не создаёт независимые события автоматически.
4. **Данные и общий исследовательский минимум:** длинная проверенная дневная цена BTC/USD (ранняя история и независимый рынок, без склейки несовместимых инструментов), макро с vintages/временем доступности, длинный ончейн и деривативы по проверенному покрытию; локальный point-in-time набор состояния и функции оценки будущей доходности, волатильности, просадки от входа и от максимума, вероятности потерь. Источники-кандидаты (Bitstamp/Kraken/Coin Metrics/ALFRED/BitMEX) проверять фактически, не считать уже доступными. Не ждать полного покрытия всех факторов; применять данные с подходящим временем/длиной истории для каждой гипотезы.
5. **Два-три ручных исследования до агентов:** (а) прогноз риска/волатильности и проверка калибровки против простых базовых моделей; (б) улучшают ли тренд, оценка стоимости, спрос или плечо момент/размер покупки против заранее определённых покупок; (в) новости и изменение режима: реакция и добавочная прогностическая ценность при достаточных эпизодах, структурированные кейсы с альтернативными объяснениями. Порядок уточнять по данным. Не отказываться от направления цены, небольших обоснованных сочетаний факторов или неожиданных новостей, но не делать массовую разметку/перебор до доказанной реализуемости.
6. **Первый агентный цикл:** один руководитель, один работник, переиспользовать harness; только разрешённые локальные инструменты, реестр гипотез и всех попыток, контроль бюджета и множественных проверок, память отрицательных результатов, закрытый итоговый набор вне инструментов. Итоговый тест только отдельным утверждённым запуском, не бесконечным API запросом даже с квотой. Никакого произвольного shell/кода LLM. Добавлять параллелизм только при измеренной пользе.
7. **Расширение:** FOMC/ETF, криптособытия, CVD/OI/ончейн и их сочетания, приоритет по пригодности данных и пользе решения. Накопление дешёвых новых наблюдений с временем доступности и сохранением версий отдельно от панели. Результаты оценивать по силе доказательств (эксплораторные, исторически проверенные, перспективно подтверждённые), внедрять осторожно. Мониторинг не менять без отдельного решения. Opus — ручной независимый аудит/проектирование; Astra — сложные исследования, источники и научный аудит по мере необходимости.

Не искать новые API без реальной необходимости.

Локальная программа считает числа, проверяет доступность данных, управляет лимитами и повторениями; модели формулируют гипотезы и оценивают смысл. Никаких прав на произвольные команды, секреты, GitHub, диск или сеть для внешних работников; инструменты только из белого списка. Учитывать расход, неизвестный usage и надбавку поставщика; не обходить тарификацию. GitHub + update.bat, без Google Drive для разработки.

## Исследовательская модель и приоритет данных
Не искать точные исторические совпадения всех индикаторов. Проверять добавочную прогностическую ценность относительно простых ориентиров, устойчивость к смене режима, издержки и риск. Сначала одиночные признаки и небольшие обоснованные сочетания; регистрировать все проверенные гипотезы, отделять разработочную выборку от итоговой и перспективной. Стратегии — вероятностные правила выбора покупки/ожидания, не гарантии и не автоторговля.

Приоритет: длинная проверенная история цены, оценка риска и решения о покупках; макроэкономические ряды с датами публикации/версиями, ФРС, дневной CVD/объём и ончейн, ETF и деривативы с подтверждённым покрытием; исторические криптособытия с временем и состоянием ожиданий. Пятибиржевой CVD, L2, опционы — накапливать и восстанавливать по доказанной необходимости, не смешивать несопоставимые ряды. Не требовать наличия всех групп на каждой дате. Проверять общую историю и число независимых эпизодов, а не число минут. Наличие данных в панели не означает их пригодность для исторической проверки.

Работники получают компактную таблицу покрытия, описание признаков и проверенные результаты предопределённых локальных инструментов (срезы, агрегаты, статистика, проверка гипотез); большие архивы не отправляются в LLM. Руководитель определяет приоритет, бюджет и критерий завершения, сопоставляет выводы; код считает и обеспечивает ограничения. Автоматический поиск комбинаций допускается только с контролем перебора и независимой проверкой. До успешного первого цикла не вводить новые уровни управления.
