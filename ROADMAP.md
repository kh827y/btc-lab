# BTC Lab — план разработки (26.11.2026)

Цель: проверять полезные для позиционного инвестора BTC закономерности на горизонте недель–месяцев (включая микротренды 1–4 недели). Приоритет — влияние новостей и их взаимодействие с ожиданиями и состоянием рынка; не считать доминирование новостей доказанным заранее.

1. **Сейчас — Astra (Work, очень высокое усилие):** предложить минимальный научно обоснованный протокол первого исследования новостей; выбрать события, метрики реакции, контрольные периоды, учёт ожиданий, времени публикации, пересекающихся событий, режимов рынка и проверки вне выборки. Определить необходимые данные, не проектировать универсальную платформу.
2. **Параллельно — GPT-6.2:** проверить исправленный дневной Binance и реализовать проверяемую локальную минутную историю BTC (с доступного начала), переиспользуя существующий код.
3. **Astra (высокое/очень высокое):** поиск и практическая проверка бесплатных исторических источников событий и ожиданий (сначала CPI/FOMC/NFP, затем криптоспецифичные новости). Отделить подтверждённое покрытие от заявленного; оценить лицензии, точность времени и доступность на момент события.
4. **GPT-6.2:** реализовать минимальный набор данных и воспроизводимый инструмент первого исследования по согласованному протоколу. Не смешивать даты наблюдения и публикации. Добавлять версии/архивы только по необходимости.
5. **Astra (очень высокое):** провести или независимо проверить первый анализ, оценить ошибки, альтернативные объяснения, устойчивость, статистическую и практическую ценность. GPT-6.2 исправляет выявленные проблемы.
6. **GPT-6.2 + Astra по необходимости:** расширить исследования на криптоспецифичные события, ETF, CVD, OI, ончейн, ликвидность и их взаимодействие с новостями. Проверять прирост прогностической ценности относительно простых базовых моделей.
7. **GPT-6.2:** внедрять в панель только полезные и проверенные результаты; изменения действующего мониторинга — по отдельному решению пользователя.

Astra используется для сложных исследовательских решений, поиска источников, нетривиальных архитектурных развилок и независимого аудита, а не ради расходования лимитов. Задания передаёт пользователь; результат сохраняем в GitHub (без секретов и больших архивов), проверяем перед реализацией. План уточняется по результатам исследований.
