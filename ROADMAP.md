# BTC-Lab — единый план (27.11.2026)

Цель — проверяемые знания для позиционного инвестора BTC (недели–месяцы), прежде всего влияние новостей, ожиданий и состояния рынка. Не автоторговля.

1. **Готово:** локальная панель и часть истории, протокол CPI, реальный архив 106 релизов (105 месячных сюрпризов), сравнительные тесты моделей и API. CPI хранится локально, лицензии прогнозов неоднородны. Не пересобирать архив и не повторять бенчмарки.
2. **Готово:** загрузчик минут Binance BTCUSDT spot с 2017-08-17, проверка SHA-256, временных границ, OHLC, пропусков; локальный аудит 99,38%, все 137 архивов приняты. Сохранить прежний дневной источник; сверить цены в исследовании.
3. **Сейчас:** импорт CPI и точное объединение по UTC завершены локально (102 пригодных события); development replay по CPI_PROTOCOL.md, затем независимая сверка и заморозка итоговой проверки; зафиксировать протокол до просмотра результата, включая альтернативные прогнозы, нестандартные релизы, календарь сопутствующих событий, train/development/test, комиссии. Программные функции для расчётов, воспроизводимый отчёт и журнал гипотез. Отрицательный/неопределённый результат допустим.
4. **Первый агентный цикл:** переиспользовать проверенные части сетевого harness; минимальный локальный Python-контроллер, ограниченные read-only инструменты, проверяемые расчёты, сохранение попыток/артефактов и бюджета. Один реальный CPI-эксперимент, один руководитель и один/несколько независимых работников по мере необходимости, тесты с имитацией сбоев и малый API smoke-test, а не повтор бенчмарков. Никакого произвольного shell или исполнения кода LLM.
5. **Astra:** независимый научный аудит первого исследования, затем сложная методология и значимые спорные результаты. По запросу владельца отдельное исследование внеплановых криптоновостей может идти параллельно, если ещё не выполнено.
6. **Масштабирование после сквозной проверки:** небольшая серия гипотез, оценка реальной стоимости, завершённости и качества; дедупликация, контроль множественных проверок, независимая проверка, сохранение отрицательных результатов. Не строить инфраструктуру для тысяч работ заранее.
7. **Расширение:** ФРС/ETF, криптособытия, индикаторы и их сочетания; внедрять только проверенные полезные результаты. Действующий мониторинг не менять без отдельного решения.

Один уровень руководства: Sol High через API, без обязательной цепочки руководителей. Astra через API — возможная замена/эскалация, не обязательный второй слой. MiniMax — опциональная проверка/резерв, подключать при измеренной потребности. Surplus/Mistral не подключать и не пополнять: баланс исчерпан, сохранить лишь исторические результаты испытаний. Локальная программа считает числа, проверяет доступность данных, управляет лимитами и повторениями; модели формулируют гипотезы и оценивают смысл. Никаких прав на произвольные команды, секреты, GitHub, диск или сеть для внешних работников; инструменты только из белого списка. Учитывать расход, неизвестный usage и надбавку поставщика; не обходить тарификацию. GitHub + update.bat, без Google Drive для разработки.

## Исследовательская модель и приоритет данных
Не искать точные исторические совпадения всех индикаторов. Проверять добавочную прогностическую ценность относительно простых ориентиров, устойчивость к смене режима, издержки и риск. Сначала одиночные признаки и небольшие обоснованные сочетания; регистрировать все проверенные гипотезы, отделять разработочную выборку от итоговой и перспективной. Стратегии — вероятностные правила выбора покупки/ожидания, не гарантии и не автоторговля.

Приоритет: длинная проверенная история цены и объёма + CPI; затем доступные макроэкономические ряды с датами публикации/версиями, ФРС, дневной CVD/объём и ончейн, ETF и деривативы с подтверждённым покрытием; исторические криптособытия с временем и состоянием ожиданий. Пятибиржевой CVD, L2, опционы — накапливать и восстанавливать по доказанной необходимости, не смешивать несопоставимые ряды. Не требовать наличия всех групп на каждой дате. Проверять общую историю и число независимых эпизодов, а не число минут. Наличие данных в панели не означает их пригодность для исторической проверки.

Работники получают компактную таблицу покрытия, описание признаков и проверенные результаты предопределённых локальных инструментов (срезы, агрегаты, статистика, проверка гипотез); большие архивы не отправляются в LLM. Руководитель определяет приоритет, бюджет и критерий завершения, сопоставляет выводы; код считает и обеспечивает ограничения. Автоматический поиск комбинаций допускается только с контролем перебора и независимой проверкой. До успешного первого цикла не вводить новые уровни управления.
