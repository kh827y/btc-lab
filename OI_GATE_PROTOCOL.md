Question D3: can the fixed price-state versus price-state+OI-feature estimator detect incremental information with 86 weekly origins (prior matched OI study scale)? Nested 156 and 260 origins (~3 and 5 years) are fixed planning sensitivities, not independent tests, and cannot rescue the primary 86-origin result. ## Data-generating process and target
Independent histories, 256 per scenario, fixed seeds 2026112901/02/03/04 for calibration null / validation null / planted / strong. Warmup 136 weeks. Markov binary regime flip .06/week; independent persistent sign signal flip .20/week. Three weekly price paths with totals log(.86), log(.99), log(1.10), fixed weekday path fractions in code, flat Saturday/Sunday returns; each synthetic daily low is min(open,close)*exp(-.005). Down probability .28+.22*regime+effect*signal, flat .18, up remainder. Fixed effects 0,0,.16,.22, selected as illustrative probability shifts before simulation; no fitting or adjustment to hit a target. Different path and confounding design from GATE-001. The synthetic OI feature equals signal + .8*prior7d_log_return/.12, known by Friday because flat weekend. Under null it is correlated with observed price but contains no extra information given the full price/regime history; a restricted fitted baseline may still exploit duplicated price information, hence empirical null calibration. This is a feature-level proxy, not full 14-Friday OI generation or a realistic BTC path model. Regime switches create dependence; no assertion of BTC-calibrated drift/volatility.

Target same synthetic counterpart of existing BUY loss15: minimum daily low over 28 days or endpoint open <=.85*Monday entry open. Past Saturday close, no Sunday data in price features; synthetic signal predetermined at origin. Mature old label only if endpoint day closed by Sunday UTC cutoff, latest t-5 weeks. Price features log EWMA sigma (60 daily returns, .94 decay, floor 1e-6), log close/MA50, log close/max180, log 28d and 7d return, same formulas as candidate price comparator. One added OI proxy, same origins and training. Last104 matured labels, min52, training-only scaling, legacy fixed ridge .1 / intercept .001 / 300 steps, reuse GATE-001 batch fitter. Two descriptive adequacy references: expanding empirical loss15 frequency and expanding volatility-scaled empirical downside distribution with Laplace probabilities on identical eligible historical origins. No selecting model or feature based on this run.

## Detection and practical size
Exact finite-path oracle computes crossing probability with current regime and latent sign, and comparator oracle integrates sign using Bayes filtering of past price categories and observed regimes. Mean squared oracle probability difference is the true conditional Brier gain in that oracle information set, not a general upper bound for empirical model gain. Compute oracle preflight for every scenario before fitting and save it. Fixed planted effects may produce true gain above/below .01: record actual magnitude; do not tune effects/seeds based on results. .01 absolute Brier gain is an illustrative diagnostic convention carried forward, NOT owner utility or an investment threshold. Do not claim power for exactly .01 if actual planted gain differs.

For each size, primary statistic mean paired baseline minus challenger Brier per independent history. Detection threshold max(0,95th percentile independent calibration-null gains); detection strictly greater than threshold. Validation false detection and planted detection assessed separately using Wilson95 across independent histories (256 balances runtime and MC precision; not a real BTC sample count). Provisional criterion null upper bound <=10%, planted lower bound >=80%. No mixing statistical detection threshold with useful-effect cutoff. Report mean and quantiles, fraction of histories gain >=.01, baseline/reference losses, oracle realized and expected gains. A synthetic diagnostic pass at primary 86 additionally requires planted oracle expected gain >=.01, planted fitted mean gain >=.01, and fixed price baseline mean Brier no worse than both expanding references in validation null and planted worlds. If reference check fails, comparator not adequate even in this toy world. Strong scenario and longer lengths only descriptive, never rescue primary. None of this constitutes real-world power proof or investment utility.

One fixed run, preserve report and separate preflight, no seed/model tuning or repeat for pass.
